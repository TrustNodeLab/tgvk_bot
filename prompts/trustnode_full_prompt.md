### Цветовые темы (по уровню угрозы) — теперь это ТОЛЬКО акцентный цвет

Фон и базовый цвет текста больше не завязаны на уровень угрозы — они завязаны на **реальное небо над Москвой** (см. следующий раздел). Уровень угрозы определяет только: акцентную полосу сверху, рамки/текст тегов, верхнюю линию карточек, крупные числа, часть заголовка.

| Уровень | Критерий (когда использовать) | Акцент (тёмное небо: ночь/сумерки) | Акцент (светлое небо: день) |
|---|---|---|---|
| **News (новость)** | Констатация факта/события, без прямого риска для читателя здесь и сейчас — анонс, статистика, нейтральная новость | `#3B82F6` | `#1D4ED8` |
| **Real threat (угроза)** | Активная схема мошенничества, конкретный кейс атаки — «это может произойти с тобой прямо сейчас» | `#EF4444` | `#B91C1C` |
| **Medium (средняя)** | Потенциальный риск, требует внимания, но не паники — тренд, отраслевая аналитика, предупреждение общего характера | `#FB923C` | `#B45309` |
| **Safe (безопасно)** | Успокаивающий/полезный контент — советы по защите, разбор мифа, позитивный кейс (мошенника поймали), инструкция «как проверить себя» | `#2DD4BF` | `#0F766E` |

**Правило контраста:** если небо светлое (день, `is_light=True` из функции неба) — берётся правая колонка (более тёмный/насыщенный акцент), иначе левая. Это не опционально — на светлом фоне левая колонка даёт слишком низкий контраст.

> Если пользователь не указал уровень угрозы — спроси, к какой из 4 категорий по смыслу ближе новость.

### Космический фон — реальное небо над Москвой (не рандомные точки)

Фон — не абстрактный шум, а **настоящее звёздное небо над Москвой** на конкретный час, посчитанное через реальную астрономию (звёздное время → высота/азимут звёзд → проекция), плюс реальная высота Солнца определяет, темно сейчас или светло.

**Ротация времени:** 5 карточек подряд используют часы `00:00 → 05:00 → 10:00 → 15:00 → 20:00`, затем цикл повторяется (`+5 часов`, по кругу от `00`). Дата — сегодняшняя (реальная дата генерации), чтобы созвездия были актуальны по сезону.

**Как это работает (кратко):**
1. Каталог ярких звёзд (реальные RA/Dec/магнитуда, ~40 звёзд) + линии созвездий (Большая Медведица, Кассиопея, Орион, Лебедь, Лира).
2. Для широты/долготы Москвы (55.7558°N, 37.6173°E) и заданного часа считается местное звёздное время (LST) → высота/азимут каждой звезды.
3. Показываются только звёзды выше горизонта, спроецированные на купол (зенит-проекция).
4. Высота Солнца в тот же час определяет: цвет неба (градиент), базовый цвет текста (белый на тёмном/светлое небо → чёрный на светлом), и прозрачность звёзд (0% днём — реализм: звёзд при свете солнца физически не видно).

```python
def julian_date(dt_utc):
    y, m, d = dt_utc.year, dt_utc.month, dt_utc.day

def altaz(ra_h, dec_deg, lst_h, lat_deg):
    H = math.radians((lst_h - ra_h) * 15.0)
    dec, lat = math.radians(dec_deg), math.radians(lat_deg)
    sin_alt = math.sin(dec)*math.sin(lat) + math.cos(dec)*math.cos(lat)*math.cos(H)

    cos_az = (math.sin(dec) - math.sin(math.radians(alt))*math.sin(lat)) / (math.cos(math.radians(alt))*math.cos(lat) + 1e-9)

    if math.sin(H) > 0:
```

**Функция рендера фона** (использует модуль выше):

```python
def lerp_color(c1, c2, t): return tuple(int(lerp(c1[i], c2[i], t)) for i in range(3))

    TWI_TOP, TWI_BOT = (18,22,52), (60,45,90)

    elif sun_alt <= 15:
        t = (sun_alt-3)/12.0
        return lerp_color(HORIZON_TOP,DAY_TOP,t), lerp_color(HORIZON_BOT,DAY_BOT,t), (17,17,17), 0.0, (t>0.5)
    else:
        return DAY_TOP, DAY_BOT, (17,17,17), 0.0, True

def project(alt, az, W, H):
    r = 90 - alt
    scale = (H*0.62)/90.0
    az_r = math.radians(az)
    return W/2 + r*math.sin(az_r)*scale, H*0.42 - r*math.cos(az_r)*scale

def draw_sky(draw, img, W, H, dt_msk):
    sun_alt = sun_altitude_moscow(dt_msk)
    top_c, bot_c, text_c, star_op, is_light = sky_theme(sun_alt)
    for y in range(H):
        draw.line([(0,y),(W,y)], fill=lerp_color(top_c, bot_c, y/H))
    if star_op > 0.01:
        positions = {}
        for name, alt, az, mag, con in stars_moscow(dt_msk):
            if alt <= -2: continue
            x, y = project(alt, az, W, H)
            if -50 < x < W+50 and -50 < y < H+50:
                positions[name] = (x, y)
                size = max(1.0, (2.2-mag)*1.15)
                b = max(60, min(255, int(255*star_op)))
                draw.ellipse([x-size,y-size,x+size,y+size], fill=(b,b,min(255,b+15)))
        line_col = (max(35,int(90*star_op))+30,)*3
        for pairs in CONSTELLATION_LINES.values():
            for a, b in pairs:
                if a in positions and b in positions:
                    draw.line([positions[a], positions[b]], fill=line_col, width=1)
    return text_c, is_light, sun_alt
```

Ротация часа для N-й карточки в серии: `hour = [0,5,10,15,20][n % 5]`, `dt = datetime.now().replace(hour=hour, minute=0, second=0)`.

### Структура карточки (сверху вниз)

Везде, где раньше было «светлая тема / тёмная тема», теперь используется вывод функции неба: `text_c, is_light, sun_alt = draw_sky(...)`. Полупрозрачные тёмные/полупрозрачные светлые плашки под карточки нужны почти всегда — небо не однотонное, поэтому у карточек обязательно должна быть своя заливка (не «прозрачно поверх неба»), иначе звёзды будут просвечивать сквозь текст.

#### 0. Акцентная полоса сверху
- На самом верхнем крае канвы, во всю ширину: полоса **8–10px**, цвет = акцент уровня угрозы (с учётом `is_light`, см. таблицу выше).

#### 1. Верхняя панель
- **Слева**: 2–3 тега в рамках, скругление **6px**, uppercase, Jura Bold **22px** (не 15px — см. правило минимумов шрифта).
  - Рамка и текст тега — акцентный цвет уровня угрозы (тот же, что и полоса сверху).
- **Справа**: `trustnodelab.github.io`, Jura Medium **20px**, цвет `text_c` с уменьшенной непрозрачностью (серый оттенок того же тона, что и `text_c`).

#### 2. Подзаголовок
- Формат: `// ТЕМА В ВЕРХНЕМ РЕГИСТРЕ`
- Jura Bold **22px**, акцентный цвет уровня угрозы.

#### 3. Заголовок (Hero)
- Exo 2, вес 900 (Black), **56–64px** (уменьшай до **48px**, если не влезает — но не ниже жёсткого минимума).
- Часть текста акцентом уровня угрозы, часть — цветом `text_c`.

#### 4. Карточки (2–5 шт., количество = число ключевых фактов из источника, НЕ фиксировано на 3)
- Раскладка зависит от количества:
  - **2 факта** → 2 крупные карточки в ряд (сравнения «было/стало», «план/факт») — можно давать текст абзацем.
  - **3–4 факта** → ряд из 3–4 карточек, при желании со стрелками между ними, если это шаги последовательности.
  - **5 фактов** → ряд из 5 узких карточек ИЛИ сетка 2 колонки × 3 строки.
- Ширина: `(W - 80 - gap*(n-1)) // n`.
- **Высота — НЕ фиксированное число**, тянется на доступное пространство (см. «Динамический размер канвы»).
- Скругление: **10px**.
- **Заливка карточки — полупрозрачная плашка поверх неба**, не прозрачная: если `is_light` → `rgba(255,255,255,0.85)`-подобная плашка (в Pillow — либо отдельный слой с альфа-каналом и `Image.alpha_composite`, либо просто плоская светлая заливка `#F5F7FAee`-подобного тона без альфы, если хочется избежать композитинга); если тёмное небо → плашка `#12141Add`-подобного тёмного тона. Смысл: звёзды не должны просвечивать сквозь текст карточки и мешать читаемости.
- Рамка: **1px**, чуть светлее/темнее заливки. Верхняя акцентная линия **4px** — цвет уровня угрозы.
- Внутри:
  - Число: Exo 2, вес 900, **40–42px**, акцент уровня угрозы.
  - Label: Jura, вес 700, **22px**, акцент, uppercase.
  - Описание: Exo 2, вес 400–500, **18px**, цвет `text_c`, перенос.
  - Padding: **24px** слева, **20px** сверху.

#### 5. Цитата / вывод
- Блок на всю ширину (минус 80px отступы), та же логика полупрозрачной плашки, что у карточек.
- Скругление **10px**, левая акцентная черта **6px** (цвет уровня угрозы).
- Текст: Exo 2, вес 400–500, **≥30px** (см. таблицу минимумов), цвет `text_c`.
- Многострочный текст центруется по вертикали рамки целиком (см. `draw_multiline_centered`).

#### 6. Футер
- Линия **1px** над футером.
- **Слева**: `Источник: [Название] · [Год]` — Jura Medium **20px**, приглушённый вариант `text_c`.
- **Справа**: `t.me/TrustNode_team` и `vk.com/trustnode` — Jura Medium **20px**, акцент уровня угрозы.

### ЖЁСТКИЕ ПРАВИЛА ПОЗИЦИОНИРОВАНИЯ ТЕКСТА В РАМКАХ (обязательно, без исключений)

**Причина ошибок:** `draw.textbbox()` возвращает метрики шрифта (ascent/descent), а не визуальные границы буквы. Если считать `y` вручную как «верх рамки + отступ», текст почти всегда смещается выше или ниже центра — именно этот класс ошибок надо исключить.

**Правило:** Y-координата текста внутри ЛЮБОЙ рамки, тега, карточки или блока НИКОГДА не вычисляется вручную через `top + padding`. Всегда используется `anchor` относительно центра/края геометрии самой рамки:

1. **Текст, который должен быть по центру рамки** (число в карточке, одиночная короткая надпись) →
   `anchor="mm"`, координаты — это `(cx, cy)` = геометрический центр прямоугольника рамки:
   ```python
   cx = (x0 + x1) // 2
   cy = (y0 + y1) // 2
   d.text((cx, cy), text, font=font, fill=color, anchor="mm")
   ```

2. **Текст прижат влево, но вертикально центрирован** (теги, футер, label в карточке) →
   `anchor="lm"`, `x` фиксированный (padding слева), `y = (y0 + y1) // 2` рамки/строки:
   ```python
   cy = (y0 + y1) // 2
   d.text((x0 + padding_left, cy), text, font=font, fill=color, anchor="lm")
   ```

3. **Многострочный текст внутри рамки** (описание в карточке, цитата) — считать построчно, но каждую строку центровать по X или Y тем же способом через `anchor`, никогда через накопленный вручную `y += line_height` без привязки к anchor на первой строке.

4. **Запрещено:** любой код вида `d.text((x0 + padding, y0 + padding), ...)` без anchor для текста, который визуально должен выглядеть отцентрованным (а не «прижатым к верхнему левому углу с отступом»). Такой паттерн допустим только для текста, который осознанно должен быть у верхнего края (например, длинный многострочный блок, где верх — это начало текста).

5. **Обязательный самоконтроль перед сохранением файла:** после написания кода пройтись по каждому текстовому элементу (теги, подзаголовок, заголовок, число в карточке, label, описание, цитата, футер) и явно подтвердить в комментарии рядом с каждым `d.text(...)`, какой anchor использован и почему — если anchor отсутствует и y посчитан вручную, это ошибка, её нужно исправить до сохранения.

6. **Функция-хелпер обязательна** — генерируй и используй вспомогательную функцию вместо ручных расчётов в каждом блоке:
   ```python
   def center_text(draw, box, text, font, fill, anchor="mm", align_x="center"):
       x0, y0, x1, y1 = box
       cy = (y0 + y1) // 2
       if align_x == "center":
           cx = (x0 + x1) // 2
           draw.text((cx, cy), text, font=font, fill=fill, anchor=anchor)
       elif align_x == "left":
           draw.text((x0, cy), text, font=font, fill=fill, anchor=anchor)
   ```

7. **Многострочный текст внутри рамки (цитата, вывод, summary-блок) — отдельный обязательный алгоритм.** Частая ошибка: текст прижимается к верхнему краю рамки, оставляя пустое место снизу — потому что y-старт считают как `y0 + padding`, а не от центра блока текста. Вместо этого весь блок строк должен центроваться по вертикали рамки целиком:
   ```python
   def draw_multiline_centered(draw, box, lines, font, fill, line_spacing=1.3, padding_x=24):
       x0, y0, x1, y1 = box
       line_height = int(font.size * line_spacing)
       total_height = line_height * len(lines)
       cy_box = (y0 + y1) // 2
       y = cy_box - total_height / 2 + line_height / 2
       for line in lines:
           draw.text((x0 + padding_x, y), line, font=font, fill=fill, anchor="lm")
           y += line_height
   ```
   Правило: если строк 1 — используется `center_text` (anchor="mm"). Если строк 2+ — обязательно `draw_multiline_centered`, никогда ручной `y0 + padding` со сложением `line_height` без привязки к центру рамки.

### ФОРМАТ ИЗОБРАЖЕНИЯ — ГИБКИЙ, ПОД КОНТЕКСТ

**16:9 — НЕ формат по умолчанию.** У 16:9 маленькая высота, из-за чего теги, подписи, футер и блок цитаты физически не помещаются с читаемым размером шрифта — на телефоне без зума не видно. Поэтому:

- **По умолчанию для ленты/поста используется 4:5 (1080×1350) или 1:1 (1080×1080)** — они дают достаточно вертикального места под все текстовые блоки.
- **16:9 — только если явно нужен формат обложки/видео-превью/сторис-заглушки** и пользователь это указал, или если контента настолько мало (1 заголовок, без карточек и цитаты), что дефицита места не возникает.
- 9:16 — для сторис, если запрошено явно.
- Модель не должна «залипать» на одном формате из прошлых генераций — выбор делается заново под объём текста каждый раз.

### ГЛАВНЫЙ ПРИОРИТЕТ — КРУПНЫЙ, ЛЕГКОЧИТАЕМЫЙ ШРИФТ

Пользователь листает ленту на телефоне — картинка должна читаться без зума и без напряжения глаз. Это важнее точного попадания в конкретный размер канвы.

**Жёсткие абсолютные минимумы в пикселях** (для канвы шириной ≥1080px; если канва уже — все значения ниже пропорционально увеличивать, никогда не уменьшать):

| Элемент | Мин. размер, px | Комментарий |
|---|---|---|
| Заголовок (H1) | ≥ 56px | обычно и так ок |
| Крупное число в карточке | ≥ 40px | обычно и так ок |
| **Текст в блоке цитаты/вывода снизу** | **≥ 30px** | реальный источник жалобы — был мельче |
| Подпись карточки (label заглавными) | ≥ 22px | реальный источник жалобы |
| **Текст внутри тегов (верхний ряд)** | **≥ 22px** | реальный источник жалобы — был мельче |
| **URL сайта в правом верхнем углу** | **≥ 20px** | реальный источник жалобы |
| **Футер: источник, ссылки t.me/vk.com** | **≥ 20px** | реальный источник жалобы |
| Категория-лейбл ("// МОШЕННИЧЕСТВО") | ≥ 22px | |

**Правило приоритета:** если при этих минимумах текст не помещается в рамку — увеличивается высота канвы/рамки (или площадь под конкретный блок), а не уменьшается шрифт ниже минимума. Уменьшение шрифта ради компактности запрещено категорически, в том числе для «второстепенных» элементов вроде футера и тегов — именно они чаще всего страдают первыми, и именно по ним обычно приходит жалоба от пользователя.

**Самопроверка перед сохранением:** пройтись по каждому текстовому элементу на макете (включая теги, URL в углу, футер, источник) и явно сверить его px-размер с таблицей выше. Если элемент мельче — увеличить, не оставлять «на глаз».

### ДИНАМИЧЕСКИЙ РАЗМЕР КАНВЫ — ГЛАВНОЕ ПРАВИЛО ПРОТИВ ПУСТОГО МЕСТА

**Ошибка, которую нужно исключить:** сначала выбирается формат канвы (например 4:5 = 1080×1350), потом в него укладывается контент — если контента меньше, чем «влезает» в выбранный формат, снизу остаётся большая пустая зона фона. Во всех эталонных референсах этой ошибки нет: там высота канвы точно соответствует контенту, пустот нет вообще или они минимальны.

**Порядок расчёта — строго в этой последовательности:**

1. Сначала считается **контент**: сколько карточек (2–5, см. выше), сколько строк в каждой карточке, есть ли блок цитаты, сколько строк в заголовке.
2. Считается, сколько пикселей по высоте нужно всем блокам при заданных минимумах шрифта (см. таблицу выше) + отступы между блоками + верхнее/нижнее поле:
   ```
   H_нужная = верхний_отступ (28)
            + высота_тегов (~50)
            + отступ
            + высота_подзаголовка (~40)
            + отступ
            + высота_заголовка (1 или 2 строки × line_height)
            + отступ (~50)
            + высота_карточек (максимальная из карточек по контенту, но не менее ~180px)
            + отступ (~24)
            + высота_блока_цитаты (если есть)
            + отступ (~40)
            + высота_футера (~60)
            + нижний_отступ (~40)
   ```
3. **Высота канвы = H_нужная**, округлённая вверх до ближайшего разумного числа. Ширина берётся стандартная (обычно 1080px для ленты). Если получившееся соотношение сторон близко к стандартному (1:1, 4:5, 3:4, 4:3, 16:9, 9:16) — округлить до него. Если нет — оставить нестандартную высоту, это нормально: главное, чтобы не было пустот, а не попадание в конкретный формат.
4. **Никогда не оставлять более ~3–5% высоты канвы пустыми** (просто фон без единого элемента) в любом месте макета — сверху, снизу, между блоками. Если после расчёта видно, что останется пустое место — либо это признак того, что контента реально мало (тогда высота канвы должна быть МЕНЬШЕ, а не оставаться на пустом фиксированном формате), либо карточки должны вырасти по высоте, забрав себе освободившееся пространство.
5. **Карточки тянутся вверх/вниз, а не остаются мелкими посреди пустоты.** Высота карточек = всё пространство между линией под заголовком и следующим блоком (цитата/футер), а не произвольные фиксированные 200px. Если у карточек короткое описание — увеличивается padding внутри карточки и/или размер текста описания (в пределах разумного), а не остаётся пустота ниже карточки.

### Шаблонный код

```python
from PIL import Image, ImageDraw, ImageFont
import textwrap
from datetime import datetime
from astro import stars_moscow, sun_altitude_moscow, CONSTELLATION_LINES  # см. модуль выше
import math

# --- РАЗМЕР: динамический, посчитан заранее под контент (см. раздел выше) ---
W, H = 1080, 1350  # пример — пересчитывать под реальный объём контента

# --- УРОВЕНЬ УГРОЗЫ (акцент), выбирается по критериям из таблицы ---
TIER = "real_threat"  # "news" | "real_threat" | "medium" | "safe"
ACCENT_DARK_BG = {"news": "#3B82F6", "real_threat": "#EF4444", "medium": "#FB923C", "safe": "#2DD4BF"}
ACCENT_LIGHT_BG = {"news": "#1D4ED8", "real_threat": "#B91C1C", "medium": "#B45309", "safe": "#0F766E"}

# --- ШРИФТЫ (вариативные, качаются один раз, путь ниже) ---
F_EXO2 = "Exo2-Variable.ttf"
F_JURA = "Jura-Variable.ttf"

def font(path, size, weight):
    f = ImageFont.truetype(path, size)
    f.set_variation_by_axes([weight])
    return f

def ts(draw, text, f):
    bbox = draw.textbbox((0, 0), text, font=f)
    return bbox[2] - bbox[0], bbox[3] - bbox[1]

def center_text(draw, box, text, f, fill, anchor="mm", align_x="center"):
    x0, y0, x1, y1 = box
    cy = (y0 + y1) // 2
    if align_x == "center":
        draw.text(((x0+x1)//2, cy), text, font=f, fill=fill, anchor=anchor)
    else:
        draw.text((x0, cy), text, font=f, fill=fill, anchor=anchor)

def draw_multiline_centered(draw, box, lines, f, fill, line_spacing=1.3, padding_x=24):
    x0, y0, x1, y1 = box
    lh = int(f.size * line_spacing)
    total = lh * len(lines)
    cy = (y0 + y1) // 2
    y = cy - total/2 + lh/2
    for line in lines:
        draw.text((x0 + padding_x, y), line, font=f, fill=fill, anchor="lm")
        y += lh

def create_card(hour_slot):
    img = Image.new('RGB', (W, H), (0,0,0))
    d = ImageDraw.Draw(img)

    # --- 0. Небо (см. функцию draw_sky из раздела "Космический фон") ---
    dt = datetime.now().replace(hour=hour_slot, minute=0, second=0, microsecond=0)
    text_c, is_light, sun_alt = draw_sky(d, img, W, H, dt)
    accent = ACCENT_LIGHT_BG[TIER] if is_light else ACCENT_DARK_BG[TIER]

    # --- 0b. Полоса сверху ---
    d.rectangle([0, 0, W, 9], fill=accent)

    f_tag = font(F_JURA, 22, 700)
    f_sub = font(F_JURA, 22, 700)
    f_hl = font(F_EXO2, 60, 900)
    f_num = font(F_EXO2, 42, 900)
    f_label = font(F_JURA, 22, 700)
    f_desc = font(F_EXO2, 18, 500)
    f_quote = font(F_EXO2, 32, 500)
    f_foot = font(F_JURA, 20, 500)
```
