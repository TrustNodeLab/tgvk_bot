# TrustNode Lab — бот автопостинга (VK + Telegram)

Бот работает как полноценный SMM-менеджер: **сам** сканирует RSS-ленты новостей,
находит темы про мошенничество/кибербезопасность, сам собирает карточку (реальное
небо над Москвой, шрифты Exo 2 / Jura, акцент по уровню угрозы) и текст поста, сам
присылает тебе превью с кнопками. Твоё дело — только подтвердить или отклонить.
Можно также вручную скинуть боту любой текст — работает так же.

Работает на **Cloudflare Worker**: webhook принимает апдейты Telegram мгновенно, а по
расписанию (раз в ~5 минут) воркер сам сканирует ленты и публикует посты со склада —
постоянно работающий процесс не нужен.

## Что нужно получить перед запуском

### 1. Telegram-бот

1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → следуй инструкциям.
2. Получишь `TELEGRAM_BOT_TOKEN` (вида `123456:AAH...`).
3. Напиши своему новому боту любое сообщение (`/start`), иначе он не сможет писать тебе первым.
4. Узнай свой `chat_id`: напиши боту, потом открой в браузере
   `https://api.telegram.org/bot<TOKEN>/getUpdates` — в ответе будет `"chat":{"id": ЧИСЛО}`.
   Это `TELEGRAM_ADMIN_CHAT_ID` — только с этим chat_id бот будет разговаривать.
5. Создай канал в Telegram, добавь бота туда **администратором** с правом публиковать.
   `TELEGRAM_CHANNEL_ID` — `@username_канала` (публичный) или числовой id вида
   `-100xxxxxxxxxx` (приватный, узнать через [@getidsbot](https://t.me/getidsbot)).

### 2. VK — токен сообщества с правом постить

1. Сообщество VK → Управление → Работа с API → Ключи доступа → Создать ключ.
2. Права — **«Стена»** (wall). Скопируй токен — `VK_TOKEN`.
3. `VK_GROUP_ID` — числовой id сообщества **без минуса** (Управление → Обзор).
4. *(Опционально)* `VK_ALBUM_ID` — id альбома сообщества (Фото → Альбомы, число из
   адресной строки `album-<group_id>_<album_id>`). Если задан, бот сначала
   загружает карточку в этот альбом и использует постоянное фото в посте, а при
   любой ошибке сам откатывается на обычную загрузку на стену. Обычный групповой
   токен VK не разрешает альбомную загрузку (error 27) — в этом случае путь
   работает как запасной и бот всё равно постит фото через
   `photos.getMessagesUploadServer`/`photos.saveMessagesPhoto`.
5. *(Опционально, эксперимент)* `VK_CARD_URL_BASE` — публичный базовый URL, где
   лежат карточки (без слэша в конце). Если задан, бот **не** загружает фото в VK
   (групповой токен не может — error 27), а постит **ссылку-карточку** с
   превью изображения: картинка публикуется по
   `VK_CARD_URL_BASE/<id>.png`, бот добавляет эту ссылку в пост. В режиме с
   Cloudflare-хранилищем (см. ниже) карточка кладётся в **R2** и раздаётся
   Worker'ом — `VK_CARD_URL_BASE` задай как URL Worker'а, например
   `https://tgvk-bot-webhook.<твой-субдомен>.workers.dev` (без `cards/` в конце —
   подставится само). Без Cloudflare карточки лежат в `data/cards/` и нужен
   публичный репозиторий или GitHub Pages. Иногда VK тянет превью с задержкой и
   первый показ может быть без картинки. Если не задан — бот постит фото обычным путём.

### 2а. Дополнительные VK-группы (мультигруппы DGC / LostLink / LostArt)

Бот умеет публиковать и в отдельные игровые/арт-сообщества по своим окнам:

- **DGC** — игровые новости (RU): RSS-ленты playground.ru / vgtimes / dtf.
  Окна (ЕКБ): 05:00, 10:00, 15:00, 20:00.
- **LostLink** — игровые новости (EN): pcgamer / polygon / eurogamer /
  rockpapershotgun / vg247. Окна (ЕКБ): 08:00, 11:00, 14:00, 17:00, 20:00.
- **LostArt** — ИИ-арты из ТГ-каналов (`@aiart`, `@aiartcommunity`, `@neuralart`,
  `@promptart`, `@aipainting`, `@psychedelic_ai`). Картинка скачивается с
  популярной стены `t.me/s/<channel>`, декодируется (JPEG/PNG → RGBA),
  конвертируется в GIF и постится **GIF-документом** (`docs.getWallUploadServer`
  → `docs.save` → `wall.post`) — это единственный способ показать картинку
  на стене групповым токеном. Окна (ЕКБ): 09:00, 12:00, 15:00, 18:00.

Каждое окно длится 30 минут и публикует ровно 1 пост; повтор слота блокируется
ключом `vk_posted:mg:<group>:<дата>:<слот>` в KV. Нужно по одному ключу на группу:

```
npx wrangler secret put VK_TOKEN_DGC      # токен с правом «Стена» группы DGC
npx wrangler secret put VK_TOKEN_LOSTLINK # то же для LostLink
npx wrangler secret put VK_TOKEN_LOSTART  # то же для LostArt
```

Токены групп заводятся так же, как основной `VK_TOKEN` (Управление → Работа с
API → Ключи доступа). Команды админу: `/mg` — статус мультигрупп,
`/mg-tick` — принудительная публикация по текущим слотам.

### 3. LLM — GigaChat (работает в РФ без VPN)

Gemini и другие зарубежные провайдеры из России недоступны без VPN, поэтому по
умолчанию бот использует **GigaChat** от Сбера.

1. Зарегистрируйся на [developers.sber.ru](https://developers.sber.ru) →
   GigaChat → Ключ авторизации. Получишь пару `client_id` и `client_secret`.
2. Склей их через двоеточие `client_id:client_secret` и закодируй в base64
   (например, командой `echo -n "id:secret" | base64`). Это `LLM_API_KEY`.
3. Задай `LLM_PROVIDER=gigachat`. Модель по желанию — `LLM_MODEL`
   (`GigaChat-Max` по умолчанию; есть также `GigaChat-Pro`, `GigaChat-Plus`,
   `GigaChat-Lite`).

Опционально, если VPN всё-таки есть: можно вернуть любого OpenAI-совместимого
провайдера (Gemini, DeepSeek, ...), просто задав `LLM_PROVIDER` пустым,
`LLM_API_KEY` — свой ключ, и при необходимости `LLM_API_BASE` / `LLM_MODEL`.

### Сертификат GigaChat (TLS)

Эндпоинты GigaChat работают на TLS-сертификате, выпущенном **Российским
доверенным ЦС (Russian Trusted Root CA)** НУЦ Минцифры — его нет в стандартных
хранилищах ОС/Python, поэтому просто так `requests` не проверит соединение
(ошибка SSL). В репозитории лежит корневой сертификат:

- **Файл:** `bot/certs/russian_trusted_root_ca.pem`
- **Источник (официальный):** портал Госуслуг
  [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt) → прямой файл
  `https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer`
  (этот же файл в PEM-виде). Это государственный корневой УЦ Минцифры, выданный
  специально для доступа к госсервисам и gigachat.devices.sberbank.ru.
- **Отпечаток (SHA-1):** `8FF915CCAB7BC16F8C5C8099D53E0E115B3AEC2F` — проверь при
  обновлении, что файл не подменили.

**Как обновить:** когда сертификат перевыпустят (сейчас действует до 28.02.2032),
скачай свежий с госуслуг и замени файл. Если проверку нужно отключить или указать
свой бандл — задай переменную окружения `GIGACHAT_CA_BUNDLE=/path/to/bundle.pem`.
Без неё и без файла сертификата бот отключит проверку TLS только в аварийном
режиме, с предупреждением в stderr — так, чтобы это было заметно, а не тихо.

## Cloudflare Worker и хранилище (Фаза 1 миграции)

Webhook принимает **Cloudflare Worker** (`worker/worker.js`), который и сканирует
RSS по расписанию. С Фазы 1 состояние бота больше не коммитится в git, а живёт в
Cloudflare:

- **KV** — `state.json`, черновики, история постов (JSON);
- **R2** — PNG: карточки (публично, для VK link-card), черновики, история.

Python-бот обращается к ним через REST-эндпоинты Worker'а (`/kv`, `/files/`),
когда заданы `BOT_WORKER_URL` и `BOT_WORKER_TOKEN`. Без них `bot/state.py`
работает в прежнем файловом режиме (для локального теста).

**Настройка один раз:**

1. В папке `worker/` создай KV-пространство и R2-бакет и подставь id в `wrangler.toml`:
   ```bash
   npx wrangler kv namespace create BOT_KV   # id -> в wrangler.toml (id и preview_id)
   npx wrangler r2 bucket create tgvk-bot-files
   ```
2. Секреты Worker:
   ```bash
   npx wrangler secret put GITHUB_TOKEN      # PAT с правами workflow
   npx wrangler secret put WEBHOOK_SECRET    # тот же secret_token из setWebhook
   npx wrangler secret put BOT_AUTH          # ключ для бота к /kv и /files/* (fallback — WEBHOOK_SECRET)
   npx wrangler secret put VK_TOKEN          # основной токен студии (стена)
   npx wrangler secret put VK_TOKEN_DGC      # мультигруппы: токен группы DGC
   npx wrangler secret put VK_TOKEN_LOSTLINK # мультигруппы: токен группы LostLink
   npx wrangler secret put VK_TOKEN_LOSTART  # мультигруппы: токен группы LostArt
   ```
3. Деплой: `npx wrangler deploy` в папке `worker/`.
4. В GitHub Actions добавь секреты `BOT_WORKER_URL` (URL Worker'а, без слэша в
   конце) и `BOT_WORKER_TOKEN` (тот же `BOT_AUTH`).

## Настройка репозитория

1. Создай **приватный** репозиторий на GitHub, залей туда всё содержимое этой папки.
2. Settings → Secrets and variables → Actions → **New repository secret**, добавь:
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `TELEGRAM_CHANNEL_ID`,
   `VK_TOKEN`, `VK_GROUP_ID`, `LLM_API_KEY`,
   `BOT_WORKER_URL`, `BOT_WORKER_TOKEN`.
   (Опционально `VK_ALBUM_ID`, `VK_CARD_URL_BASE` — см. раздел про VK выше.)
   **Variables**: `LLM_PROVIDER=gigachat`, при желании `LLM_MODEL`.
3. Settings → Actions → General → Workflow permissions → **Read and write permissions**.
4. Actions → «TrustNode bot poll» → **Run workflow** — первый ручной запуск,
   дальше идёт по расписанию само.

## Как это работает на практике

Каждые ~5 минут воркер:

1. Проверяет, не написал ли ты ему что-то новое или не нажал ли кнопку на старом превью.
2. **Сам** сканирует ленты из `config/sources.json`, ищет новые заметки по ключевым
   словам темы, докачивает текст статьи, прогоняет через LLM → получает JSON
   → рисует карточку → присылает тебе превью с пометкой «🔍 Бот нашёл новость сам».
   Свежие кандидаты копятся в очереди.
3. По окну собирается **дайджест**: одна сводка из 3–5 свежих новостей
   (факт + ссылка + блок «Что делать») с общей обложкой. Выпуски — трижды в день:
   утро (09:00), день (13:00), вечер (18:00 МСК), чтобы канал выглядел как живая
   редакция, а не спам-лента. Автопостинг вкл — выпуск уходит в TG+VK сам; выкл —
   админу приходит дайджест-превью на одобрение. Ивенты публикуются в заданное время.
4. Об успешной публикации и о догонке недостающей платформы (если VK или TG не
   ответили с первой попытки) бот присылает уведомление со ссылкой на пост.

## Студия: статистика и управление расписанием

Бот ведёт себя как живая редакция — следит за охватами и сам подстраивает график
выхода постов. Всё управление — из чата с ботом, на русском.

- **/stats** — статистика с «скриншотом»: бот рисует PNG-дашборд (постов всего и
  за сегодня, средние просмотры и реакции, вовлечённость, текущее расписание,
  лучшие жанры/темы/схемы, топ постов) и присылает его как фото + текстовую сводку.
  Здесь же видно, **что залетает** (какой контент набирает просмотры лучше
  остального) — воркер анализирует `publish_log` и раскладывает «залётность» по
  жанрам, темам и схемам карточек.
- **/top** — разбор залётности по жанрам/темам/схемам с баллами; лучшие связки
  (например, «тема X + жанр Y» дают стабильно высокие просмотры) учитываются при
  выборе контента для новых постов.
- **/schedule** — текущее расписание и его настройка кнопками:
  - **Авто** — бот сам решает: если средние просмотры за 7 дней < 1200 — добавляет
    обеденный слот (12:00 МСК); < 6000 (точнее, ниже планки) — убирает лишний.
    Решение принимается не чаще раза в сутки и только по статистике реальных постов.
  - **Вручную** — режим «студии»: кнопки **+** / **−** добавляют или убирают
    дополнительные слоты, **Сброс** возвращает базовую сетку.
  - Базовая сетка — утро/день/вечер (09:00, 13:00, 18:00 МСК), её нельзя убрать
    совсем; дополнительные слоты (обед ~12:00 и предвечерье ~17:00) появляются и
    исчезают по охватам или по вашей команде.
- При изменении расписания автоматически бот присылает админу уведомление с
  причиной (например, «Просмотры упали — добавлен обеденный выпуск»).

## Отчёты студии (растём каждый день)

Бот каждый день измеряет результат: посты, охваты, лайки, реакции и подписчиков
(TG-канала и VK-группы). Вся история копится в день-метриках, по ним студия
сама присылает отчёты:

- **Вечером 20:00 (МСК)** — 🌆 вечерняя сводка: сколько постов, просмотров,
  лайков и реакций получили за день (+ дельты к вчера) и сколько подписчиков
  прибавилось в TG и VK.
- **В 23:30** — 📋 отчёт за день: чего достигли, сравнение со вчера, лучший пост
  дня, лучший жанр/тема и совет студии «делаем в этом же ключе».
- **В воскресенье 20:30** — 🗓 недельная сводка: неделя против прошлой недели
  (+проценты) и рост подписчиков.
- **1-го числа 20:30** — 📅 месячная сводка: месяц против прошлого месяца.
- **/report** — запросить любой отчёт вручную: `/report вечер`, `/report день`,
  `/report неделя`, `/report месяц`.

Отчёт считается по реальным охватам: просмотры/лайки/репосты VK опрашиваются
раз в час (`wall.getById`), реакции TG приходят в реальном времени через webhook.
Подписчики снимаются при сборе метрик (раз в день). Каждый отчёт уходит ровно
один раз (маркеры анти-дубля), чтобы канал не спамило при перекрытии крон-тиков.

Под любым превью (найденным ботом или из твоего текста) — пять кнопок:
- **🌐 Опубликовать везде** — сразу в VK-стену и в Telegram-канал.
- **🔵 В VK** / **🟢 В TG** — опубликовать только в одну платформу.
- **🔄 Переделать** — просит прислать текст ещё раз с уточнениями (пересборка с нуля).
- **❌ Отменить** — черновик удаляется, никуда не публикуется.

### Настройка тем поиска

`config/sources.json` — список RSS-лент и ключевых слов, по которым бот отбирает
новости. Правится напрямую в GitHub (Edit файла в браузере) без изменения кода:

```json
{
  "feeds": ["https://ria.ru/export/rss2/index.xml", "..."],
  "keywords": ["мошенник", "фишинг", "..."]
}
```

Добавляй свои ленты и слова — источник ошибок здесь один: слишком общее слово
(например, просто «банк») даст много нерелевантных совпадений. LLM дополнительно
сам отсеивает явно нерелевантные находки (см. `prompts/extract_prompt.md`) и просто
не присылает по ним черновик — но лучше держать ключевые слова прицельными.

## Ограничения текущей версии (MVP)

- Задержка до ~5 минут на любое действие — потолок бесплатного расписания Cloudflare (крон).
- Кандидаты копятся в очереди и попадают в выпуск (дайджест 3–5 новостей) в ближайшее
  окно — размер выпуска регулируется `DIGEST_MIN_ITEMS` / `DIGEST_MAX_ITEMS`
  в `worker/lib/config.js`.
- Извлечение текста статьи — простое regex-по-`<p>`, без специальной библиотеки
  чтения статей; на некоторых сайтах со сложной вёрсткой текст может вытянуться
  не полностью — тогда LLM просто соберёт карточку по меньшему объёму фактов.
- «Переделать» — пересборка с нуля по тексту, не точечная правка одного поля карточки.
- Для карточек с 5 фактами используется раскладка «в ряд» (сетка 2×3 из
  мастер-промпта сюда пока не перенесена).
- В режиме с Cloudflare (KV/R2) черновики и история хранятся в Cloudflare, а не в
  git — коммитов каждый запуск больше нет. Без Cloudflare (файловый mode) черновики
  по-прежнему лежат в `data/` — приватный репозиторий тогда обязателен.

## Структура проекта

```
bot/
  main.py            — оркестратор одного цикла (запускается workflow'ом)
  telegram_api.py     — обёртка над Telegram Bot API
  vk_api.py            — обёртка над VK API (загрузка фото + wall.post)
  llm.py                — вызов LLM (GigaChat по умолчанию, любой OpenAI-совместимый опционально)
  news_sources.py        — автопоиск: RSS-ленты + фильтр по ключевым словам + скачивание статьи
  card_generator.py       — рендер карточки: статичный PNG или анимированный GIF (мерцающие звёзды)
  astro.py                  — реальная астрономия (звёзды/Солнце над Москвой)
  state.py                    — чтение/запись состояния и черновиков (Cloudflare KV/R2 через Worker, файловый fallback)
config/
  sources.json                  — RSS-ленты и ключевые слова (редактируется без кода)
fonts/                            — Exo 2 и Jura (вариативные, OFL-лицензия)
prompts/
  extract_prompt.md                 — системный промпт LLM (текст → JSON)
  trustnode_full_prompt.md            — полный дизайн-промпт (справочно/для ручной генерации)
data/
  state.json                            — last_update_id + список увиденных guid новостей
  drafts/                                — черновики на согласовании (JSON + PNG)
.github/workflows/poll.yml                — запасной контур подготовки (workflow_dispatch от воркера)
```

## Структура воркера

```
worker/
  worker.js            — Cloudflare Worker: webhook Telegram + REST API + планировщик
```

## Рендер-сервис (GIF/PNG)

- **Встроенный JS-рендер в воркере** (`worker/lib/cardgen.js`) — чистый JS, без Canvas/PIL. Рисует статичный PNG и **анимированный GIF**: реальное небо над Москвой (порт `bot/astro.py`), мерцающие звёзды с индивидуальной фазой, «дыхание» градиента. Работает всегда, без внешних сервисов.
- Python-рендер (`bot/render_service.py`) — тот же код в виде HTTP-сервиса (FastAPI + Pillow). Может использоваться как внешний рендер, адреса задаются в воркере через `CARD_RENDER_URLS` (список через запятую) или `CARD_RENDER_URL` (одиночный); воркер перебирает их по очереди и при недоступности падает на JS-фолбэк.
- Формат:
  - **auto** (по умолчанию): GIF когда доступен внешний рендер или JS-фолбэк, PNG при запросе png;
  - **gif**: всегда GIF-анимация;
  - **png**: всегда статичный PNG.
- Переключение: `/cardfmt gif|png|auto` (в `/settings` видно текущий). Формат можно форсировать на конкретный пост через `meta.format`.

Как карточка попадает в посты:
- **Telegram**: GIF идёт как анимация (`sendAnimation`), PNG как фото (`sendPhoto`) — воркер определяет по magic-байтам.
- **VK**: карточка грузится как GIF-документ (VK рендерит его встроенной картинкой). Если карточка уже GIF — грузится как есть, PNG конвертируется в индексированный GIF на лету.
- В момент публикации карточка перерисовывается: небо под **реальное** время выхода поста (МСК), а не под время генерации.

## AI Video Factory — вертикальные видео-дайджесты (`.video`)

Отдельный контур «фабрики видео»: **Cloudflare Worker — только API и оркестратор,
GitHub Actions — вычислительная среда рендера**. Worker никогда не рендерит сам.

### Как работает

1. Пользователь пишет боту `/video <тема>` (или нажимает «🎬 Видео из новостей» —
   Worker сам соберёт 3–5 свежих новостей из лент и составит тему).
2. Worker создаёт job в KV (`vf:job:<id>`, индекс `vf:jobs`, TTL 7 дней) и
   диспатчит GitHub Actions workflow `video-render.yml` **только с job_id**
   (никаких секретов в inputs).
3. Раннер забирает payload из Worker по `GET /api/video/<id>` (заголовок
   `X-Bot-Auth: BOT_WORKER_TOKEN`), гоняет пайплайн `video_factory/`:
   сценарий (LLM) → сцены → TTS (голос ведёт таймлайн) → визуал (Pexels/генерация)
   → умный кроп 9:16 + motion → субтитры (SRT/ASS, вшитые) → аудио-микс с дакингом
   → FFmpeg рендер (H.264/AAC/yuv420p/faststart, 720×1280@30) → валидация (ffprobe)
   → превью → загрузка в R2 через Worker `/files/`.
4. Раннер шлёт HMAC-подписанный callback (`POST /api/video/callback`, подпись
   SHA-256 над `timestamp.body`, защита от replay), Worker обновляет job.
5. Worker доставляет MP4 + EDL в чат пользователя (`sendVideo`) и уведомляет админа.

Прогресс в любой момент: `/vstatus <jobId>`.

### REST API воркера

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/video` | создать job `{topic, preset?}` → `{jobId}` |
| GET | `/api/video/<id>` | полный job (нужен `X-Bot-Auth`) |
| GET | `/api/video/<id>/status` | статус/прогресс/ошибка/ссылка на файл |
| POST | `/api/video/<id>/cancel` | отменить (409, если завершён) |
| POST | `/api/video/<id>/retry` | перезапустить failed/cancelled |
| POST | `/api/video/callback` | HMAC-callback от раннера |

Стадии и прогресс: init 0 → script 10 → plan 15 → tts 25 → assets 40 → render 60
→ validate 85 → upload 95 → done 100.
