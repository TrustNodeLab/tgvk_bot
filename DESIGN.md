# Дизайн: SMM-студия TrustNode (Cloudflare Worker)

## Цель
Автономная публикация постов **с карточками**, работающая без своей машины и без
GitHub (автопостинг целиком в воркере). Бесплатно, без привязки карт.

## Принцип
Карточку не обязательно рисовать в момент поста. Готовые посты (текст + картинка)
заранее складываются в «склад» (Cloudflare KV/R2). Публикация — это просто
HTTP-загрузка готовой картинки, что Worker делает без тяжёлого CPU. Карточка
перерендеривается в момент публикации, чтобы небо на ней соответствовало
реальному времени суток.

## Формат карточки (PNG / GIF)
- Рендер карточки — **встроенный JS-рендер воркера** (`worker/lib/cardgen.js`, чистый JS без Canvas/PIL): рисует статичный **PNG** или анимированный **GIF** (реальное небо над Москвой — порт `bot/astro.py`; звёзды мерцают с индивидуальной фазой, градиент «дышит»). Работает всегда, без внешних сервисов.
- Опционально внешние рендер-сервисы (Python `bot/render_service.py`): адреса в `CARD_RENDER_URLS` / `CARD_RENDER_URL`, воркер перебирает их по очереди и при недоступности падает на JS-фолбэк.
- Выбор формата: настройка `card_format` (auto|gif|png), переключение `/cardfmt`; `meta.format` форсирует формат для конкретного поста.
- Telegram: GIF → `sendAnimation`, PNG → `sendPhoto` (выбор по magic-байтам).
- VK: картинка всегда уходит GIF-документом (VK рендерит его встроенной картинкой);
  PNG конвертируется в индексированный GIF на лету, уже-GIF грузится как есть.

## Один контур (всё в Worker)
- Worker-крон (каждые 5 мин) сканирует фиды, **дедуплицирует** одинаковые
  новости и копит свежих кандидатов в очередь.
- По наступлению окна собирается **дайджест**: 3–5 новостей одним выпуском
  (факт + ссылка на источник + общий блок «Что делать») с одной обложкой.
  Автопостинг ВКЛ — выпуск уходит в TG+VK сам; ВЫКЛ — админу приходит
  дайджест-превью на одобрение (кнопки 🌐/🔵/🟢/🔄/❌).
- Планировщик: по наступлению слота публикует в TG + VK (строгий пул — пост
  выходит только при успехе в обеих платформах, недостающая догоняется
  ретраями на следующих тиках).
- Admin-поток: черновик с кнопками 🌐/🔵/🟢/🔄/❌. Нет ответа 30 минут -> пост
  уходит в ближайший свободный слот (отложенный).
- GitHub-контур (workflow_dispatch) оставлен только для ручных постов админа
  (`/draft`); аварийного текстового фолбэка и автодиспатча кандидатов нет.

## Расписание слотов (МСК)
- Три дайджеста в день — одна сводка 3–5 свежих новостей: утро (09:00),
  день (13:00), вечер (18:00). Публикация — в начале окна, без рандома.
- Экстренные/мало новостей: выпуск выходит с тем, что накопилось (1–2 новости).
- Ивенты публикуются в заданное админом время (текстовый пост без карточки).

## Адаптивное расписание (студия)
- Режимы: `auto` (по умолчанию) и `manual`. Состояние — KV `schedule_state`
  (`{ mode, windows, updated_at, reason }`), модуль `worker/lib/schedule.js`.
- База: 3 окна (утро/день/вечер 09/13/18 МСК) — всегда остаются (MIN_SLOTS=3).
  Дополнительные слоты (`EXTRA_WINDOWS`): обед ~12:00 и предвечерье ~17:00 —
  заполняют паузы без пересечения с базой, максимум 5 слотов (MAX_SLOTS).
- Авто-корректировка (`maybeAdjustSchedule`): раз в сутки (кулдаун 24 ч) по
  средним просмотрам постов за 7 дней (нужно ≥3 поста в окне): просмотры ниже
  ~1200 → добавить обеденный слот; выше ~6000 → убрать лишний. Только в режиме
  `auto`; добавляются/убираются только доп. слоты, база неприкосновенна.
  Изменение расписания → уведомление админу с причиной.
- Ручное управление: /schedule — кнопки `sched:auto`, `sched:manual`, `sched:plus`,
  `sched:minus`, `sched:reset`. `plus`/`minus` добавляют/убирают доп. слоты
  (в пределах MIN/MAX), `reset` возвращает базовую сетку.
- Планировщик читает окна динамически (`getWindows`), поэтому все сборщики
  дайджестов и свободные слоты учитывают текущее расписание на момент тика.

## Статистика «что залетает» + дашборд
- Анализ `publish_log` (`worker/lib/stats.js`): посты раскладываются по жанрам,
  темам и схемам карточек; считается «залётность» (просмотры и реакции), лидеры
  и топы. Лучшие связки (тема+жанр) поднимают приоритет похожего контента при
  выборе новостей (topic-буст).
- **/stats**: PNG-дашборд (картинка-«скриншот» 1080×1350, `renderDashboard` в
  `cardgen.js`) — 4 панели метрик (постов всего/сегодня, средние просмотры,
  средние реакции), вовлечённость, текущее расписание, лучшие жанры/темы/схемы,
  топ постов — отправляется фото + текстовая сводка с русскими подписями.
- **/top**: текстовый разбор залётности по жанрам/темам/схемам с баллами.

## Отчёты студии (день/неделя/месяц)
- Ежедневные метрики (`worker/lib/analytics.js` + KV `day_metrics:<date>`):
  посты, просмотры, лайки, реакции, репосты, вовлечённость за день (МСК) +
  подписчики TG-канала (`getChatMemberCount`) и VK-группы
  (`groups.getById` fields=members_count). Сбор — идемпотентный, перезаписывает
  запись дня.
- Автопубликация (`maybeSendReports`, вызывается в тике планировщика):
  - 20:00 МСК — 🌆 вечерняя сводка: метрики дня + дельты к вчера + рост подписчиков;
  - 23:30 — 📋 отчёт за день: достижения, сравнение со вчера, лучший пост,
    лучший жанр/тема, совет студии;
  - вс 20:30 — 🗓 недельная сводка (7 дней против предыдущих 7, %);
  - 1-го 20:30 — 📅 месячная сводка (30 дней против предыдущих 30).
- Маркеры KV `report_sent:<тип>:<период>` — один отчёт за период даже при
  перекрытии крон-тиков. Ручной запрос — `/report вечер|день|неделя|месяц`.
- Малоданных (менее дня) недельный/месячный отчёт не шлёт.

## Дедуп и суммаризация
- Нормализация заголовка (регистр, пунктуация, суффиксы «— Издание»).
- Схожесть по токенам (Jaccard, порог ~0.7 = та же новость).
- Из группы дублей берём источник с наибольшей подробностью (длиннее текст).

## Свежесть
Окно 24 часа (MAX_AGE_MS), приоритет последним 6 часам, чтобы склад не отдавал
старьё. Протухшие кандидаты/черновики/посты со склада выкидываются тихо.

## Ограничения (заложены)
- Free Worker: <=50 подзапросов/вызов -> скан дробится на 2 части (по ~25 фидов
  за крон, цикл из 2 крон). CPU 10 мс -> Worker не рисует и не парсит тяжело
  (только лёгкий дедуп + постинг + перерендер карточки по данным пакета).

## Хранение (KV)
- `state` — настройки: seen_guids, autopost, dry_run, blacklist, ключевые слова,
  счётчики.
- `candidates` — очередь свежих кандидатов (копится до окна, из неё собирается
  выпуск).
- `stock` — очередь готовых к публикации пакетов (JSON + PNG), включая дайджесты.
- `draft:<id>` — черновики на ручном апруве (в т.ч. дайджест-превью).
- `digest_done:<date>:<slug>` — маркер «выпуск окна собран» (анти-дубль).
- `publish_log` — история публикаций (для /stats, /export).
- `vk_retry:<id>` — догонка недостающей платформы в строгом пуле (missing: vk|tg).
- `scheduler_lock` — KV-лок против перекрытия крон-тиков.
- `schedule_state` — текущее расписание (mode, windows, updated_at, reason).
- `day_metrics:<date>` — метрики дня (посты/охваты/подписчики).
- `report_sent:<тип>:<период>` — маркеры отправленных отчётов (анти-дубль).

## Тестирование
- Dry-run режим: полная симуляция публикации без отправки в реальные каналы.
- Модульные тесты Worker (node:test, стаб KV/R2/fetch), Python-тесты (unittest,
  мок GigaChat/TG/VK), E2E-симуляция без реальных публикаций.
