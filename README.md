# TrustNode Lab — бот автопостинга (VK + Telegram)

Бот работает как полноценный SMM-менеджер: **сам** сканирует RSS-ленты новостей,
находит темы про мошенничество/кибербезопасность, сам собирает карточку (реальное
небо над Москвой, шрифты Exo 2 / Jura, акцент по уровню угрозы) и текст поста, сам
присылает тебе превью с кнопками. Твоё дело — только подтвердить или отклонить.
Можно также вручную скинуть боту любой текст — работает так же.

Работает на GitHub Actions по расписанию **раз в ~5 минут** — это ограничение
самого GitHub (постоянно работающий процесс бесплатно не даётся), не баг.

## Что нужно получить перед запуском

### 1. Telegram-бот

1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → следуй инструкциям.
2. Получишь `TELEGRAM_BOT_TOKEN` (вида `123456:AAH...`).
3. Напиши своему новому боту любое сообщение (`/start`), иначе он не сможет писать тебе первым.
4. Узнай свой `chat_id`: напиши боту, потом открой в браузере
   `https://api.telegram.org/bot<TOKEN>/getUpdates` — в ответе будет `"chat":{"id": ЧИСЛО}`.
   Это `TELEGRAM_ADMIN_CHAT_ID` — только с этим chat_id бот будет разговаривать.
5. Создай канал в Telegram, добавь бота туда **администратором** с правом публиковать.
   `TELEGRAM_CHANNEL_ID` — `@username_канала` (публичный) или числовой id вида
   `-100xxxxxxxxxx` (приватный, узнать через [@getidsbot](https://t.me/getidsbot)).

### 2. VK — токен сообщества с правом постить

1. Сообщество VK → Управление → Работа с API → Ключи доступа → Создать ключ.
2. Права — **«Стена»** (wall). Скопируй токен — `VK_TOKEN`.
3. `VK_GROUP_ID` — числовой id сообщества **без минуса** (Управление → Обзор).
4. *(Опционально)* `VK_ALBUM_ID` — id альбома сообщества (Фото → Альбомы, число из
   адресной строки `album-<group_id>_<album_id>`). Если задан, бот сначала
   загружает карточку в этот альбом и использует постоянное фото в посте, а при
   любой ошибке сам откатывается на обычную загрузку на стену. Обычный групповой
   токен VK не разрешает альбомную загрузку (error 27) — в этом случае путь
   работает как запасной и бот всё равно постит фото через
   `photos.getMessagesUploadServer`/`photos.saveMessagesPhoto`.
5. *(Опционально, эксперимент)* `VK_CARD_URL_BASE` — публичный базовый URL, где
   лежат карточки (без слэша в конце). Если задан, бот **не** загружает фото в VK
   (групповой токен не может — error 27), а постит **ссылку-карточку** с
   превью изображения: картинка публикуется по
   `VK_CARD_URL_BASE/<id>.png`, бот добавляет эту ссылку в пост. В режиме с
   Cloudflare-хранилищем (см. ниже) карточка кладётся в **R2** и раздаётся
   Worker'ом — `VK_CARD_URL_BASE` задай как URL Worker'а, например
   `https://tgvk-bot-webhook.<твой-субдомен>.workers.dev` (без `cards/` в конце —
   подставится само). Без Cloudflare карточки лежат в `data/cards/` и нужен
   публичный репозиторий или GitHub Pages. Иногда VK тянет превью с задержкой и
   первый показ может быть без картинки. Если не задан — бот постит фото обычным путём.

### 3. LLM — GigaChat (работает в РФ без VPN)

Gemini и другие зарубежные провайдеры из России недоступны без VPN, поэтому по
умолчанию бот использует **GigaChat** от Сбера.

1. Зарегистрируйся на [developers.sber.ru](https://developers.sber.ru) →
   GigaChat → Ключ авторизации. Получишь пару `client_id` и `client_secret`.
2. Склей их через двоеточие `client_id:client_secret` и закодируй в base64
   (например, командой `echo -n "id:secret" | base64`). Это `LLM_API_KEY`.
3. Задай `LLM_PROVIDER=gigachat`. Модель по желанию — `LLM_MODEL`
   (`GigaChat-Max` по умолчанию; есть также `GigaChat-Pro`, `GigaChat-Plus`,
   `GigaChat-Lite`).

Опционально, если VPN всё-таки есть: можно вернуть любого OpenAI-совместимого
провайдера (Gemini, DeepSeek, ...), просто задав `LLM_PROVIDER` пустым,
`LLM_API_KEY` — свой ключ, и при необходимости `LLM_API_BASE` / `LLM_MODEL`.

### Сертификат GigaChat (TLS)

Эндпоинты GigaChat работают на TLS-сертификате, выпущенном **Российским
доверенным ЦС (Russian Trusted Root CA)** НУЦ Минцифры — его нет в стандартных
хранилищах ОС/Python, поэтому просто так `requests` не проверит соединение
(ошибка SSL). В репозитории лежит корневой сертификат:

- **Файл:** `bot/certs/russian_trusted_root_ca.pem`
- **Источник (официальный):** портал Госуслуг
  [gosuslugi.ru/crt](https://www.gosuslugi.ru/crt) → прямой файл
  `https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer`
  (этот же файл в PEM-виде). Это государственный корневой УЦ Минцифры, выданный
  специально для доступа к госсервисам и gigachat.devices.sberbank.ru.
- **Отпечаток (SHA-1):** `8FF915CCAB7BC16F8C5C8099D53E0E115B3AEC2F` — проверь при
  обновлении, что файл не подменили.

**Как обновить:** когда сертификат перевыпустят (сейчас действует до 28.02.2032),
скачай свежий с госуслуг и замени файл. Если проверку нужно отключить или указать
свой бандл — задай переменную окружения `GIGACHAT_CA_BUNDLE=/path/to/bundle.pem`.
Без неё и без файла сертификата бот отключит проверку TLS только в аварийном
режиме, с предупреждением в stderr — так, чтобы это было заметно, а не тихо.

## Cloudflare Worker и хранилище (Фаза 1 миграции)

Webhook принимает **Cloudflare Worker** (`worker/worker.js`), который и сканирует
RSS по расписанию. С Фазы 1 состояние бота больше не коммитится в git, а живёт в
Cloudflare:

- **KV** — `state.json`, черновики, история постов (JSON);
- **R2** — PNG: карточки (публично, для VK link-card), черновики, история.

Python-бот обращается к ним через REST-эндпоинты Worker'а (`/kv`, `/files/`),
когда заданы `BOT_WORKER_URL` и `BOT_WORKER_TOKEN`. Без них `bot/state.py`
работает в прежнем файловом режиме (для локального теста).

**Настройка один раз:**

1. В папке `worker/` создай KV-пространство и R2-бакет и подставь id в `wrangler.toml`:
   ```bash
   npx wrangler kv namespace create BOT_KV   # id -> в wrangler.toml (id и preview_id)
   npx wrangler r2 bucket create tgvk-bot-files
   ```
2. Секреты Worker:
   ```bash
   npx wrangler secret put GITHUB_TOKEN      # PAT с правами workflow
   npx wrangler secret put WEBHOOK_SECRET    # тот же secret_token из setWebhook
   npx wrangler secret put BOT_AUTH          # ключ для бота к /kv и /files/* (fallback — WEBHOOK_SECRET)
   ```
3. Деплой: `npx wrangler deploy` в папке `worker/`.
4. В GitHub Actions добавь секреты `BOT_WORKER_URL` (URL Worker'а, без слэша в
   конце) и `BOT_WORKER_TOKEN` (тот же `BOT_AUTH`).

## Настройка репозитория

1. Создай **приватный** репозиторий на GitHub, залей туда всё содержимое этой папки.
2. Settings → Secrets and variables → Actions → **New repository secret**, добавь:
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `TELEGRAM_CHANNEL_ID`,
   `VK_TOKEN`, `VK_GROUP_ID`, `LLM_API_KEY`,
   `BOT_WORKER_URL`, `BOT_WORKER_TOKEN`.
   (Опционально `VK_ALBUM_ID`, `VK_CARD_URL_BASE` — см. раздел про VK выше.)
   **Variables**: `LLM_PROVIDER=gigachat`, при желании `LLM_MODEL`.
3. Settings → Actions → General → Workflow permissions → **Read and write permissions**.
4. Actions → «TrustNode bot poll» → **Run workflow** — первый ручной запуск,
   дальше идёт по расписанию само.

## Как это работает на практике

Каждые ~5 минут бот:

1. Проверяет, не написал ли ты ему что-то новое или не нажал ли кнопку на старом превью.
2. **Сам** сканирует ленты из `config/sources.json`, ищет новые заметки по ключевым
   словам темы, докачивает текст статьи, прогоняет через Gemini → получает JSON
   → рисует карточку → присылает тебе превью с пометкой «🔍 Бот нашёл новость сам».
   За один проход — не больше одного автонайденного черновика (чтобы не заваливать
   и беречь бесплатный лимит).
3. Под любым превью (найденным ботом или из твоего текста) — три кнопки:
   - **✅ Опубликовать** — сразу в VK-стену и в Telegram-канал.
   - **✏️ Заново** — просит прислать текст ещё раз с уточнениями (пересборка с нуля).
   - **❌ Отмена** — черновик удаляется, никуда не публикуется.

### Настройка тем поиска

`config/sources.json` — список RSS-лент и ключевых слов, по которым бот отбирает
новости. Правится напрямую в GitHub (Edit файла в браузере) без изменения кода:

```json
{
  "feeds": ["https://ria.ru/export/rss2/index.xml", "..."],
  "keywords": ["мошенник", "фишинг", "..."]
}
```

Добавляй свои ленты и слова — источник ошибок здесь один: слишком общее слово
(например, просто «банк») даст много нерелевантных совпадений. LLM дополнительно
сам отсеивает явно нерелевантные находки (см. `prompts/extract_prompt.md`) и просто
не присылает по ним черновик — но лучше держать ключевые слова прицельными.

## Ограничения текущей версии (MVP)

- Задержка до ~5 минут на любое действие — потолок бесплатного GitHub Actions.
- Не больше одного автонайденного черновика за проход — сознательное ограничение,
  чтобы не заваливать тебя черновиками; можно поднять `max_items` в `main.py`,
  если бесплатного лимита Gemini хватает с запасом.
- Извлечение текста статьи — простое regex-по-`<p>`, без специальной библиотеки
  чтения статей; на некоторых сайтах со сложной вёрсткой текст может вытянуться
  не полностью — тогда LLM просто соберёт карточку по меньшему объёму фактов.
- «Заново» — пересборка с нуля по тексту, не точечная правка одного поля карточки.
- Для карточек с 5 фактами используется раскладка «в ряд» (сетка 2×3 из
  мастер-промпта сюда пока не перенесена).
- В режиме с Cloudflare (KV/R2) черновики и история хранятся в Cloudflare, а не в
  git — коммитов каждый запуск больше нет. Без Cloudflare (файловый mode) черновики
  по-прежнему лежат в `data/` — приватный репозиторий тогда обязателен.

## Структура проекта

```
bot/
  main.py            — оркестратор одного цикла (запускается workflow'ом)
  telegram_api.py     — обёртка над Telegram Bot API
  vk_api.py            — обёртка над VK API (загрузка фото + wall.post)
  llm.py                — вызов LLM (GigaChat по умолчанию, любой OpenAI-совместимый опционально)
  news_sources.py        — автопоиск: RSS-ленты + фильтр по ключевым словам + скачивание статьи
  card_generator.py       — рендер PNG-карточки (небо + шрифты + вёрстка)
  astro.py                  — реальная астрономия (звёзды/Солнце над Москвой)
  state.py                    — чтение/запись состояния и черновиков (Cloudflare KV/R2 через Worker, файловый fallback)
config/
  sources.json                  — RSS-ленты и ключевые слова (редактируется без кода)
fonts/                            — Exo 2 и Jura (вариативные, OFL-лицензия)
prompts/
  extract_prompt.md                 — системный промпт LLM (текст → JSON)
  trustnode_full_prompt.md            — полный дизайн-промпт (справочно/для ручной генерации)
data/
  state.json                            — last_update_id + список увиденных guid новостей
  drafts/                                — черновики на согласовании (JSON + PNG)
.github/workflows/poll.yml                — расписание запуска (раз в 5 минут)
```
